# 2026-09-30

## 修复「超时自动切换不生效」+「全部测速很慢」

用户报：手动点测试当前节点、或已经测出当前节点超时，却迟迟不换节点；全部测速很慢、性能差。

### 取证（真机，ZTE U30Pro 192.168.0.1 / 猫猫 mihomo v1.19.19）
- `defaults read dev.don.ClashRemote`：`autoFailoverInterval=5`，开关未持久化 → 默认 true；
  `failoverHistory` 80 条（已满），最新一条就在读取前 ~20 秒 → **自动换节点其实一直在跑**。
- 解码历史：在 `🌏 新加坡01 / 🇯🇵 日本01 / 🇯🇵 日本02` 之间每 40~260s 来回跳，延迟都只有 60~90ms。
- 设备守护日志：`timeout X, probing all` → **60~70 秒后**才 `switched`。
- 单节点 `/proxies/{name}/delay`：好节点 0.2s，死节点 **正好 5.0s（504）**；8 并发跑 7 个节点也要 5.4s
  （被批次里最慢的那个拖满）。
- `GET /group/选择节点/delay?timeout=…`：**一个请求 85 个成员，耗时 ≈ timeout**，返回 55~56 个测通的；
  与 `/proxies` 的 `history.delay==0` 交叉验证 → **缺失 = 超时**。
- 组内混着 `剩余流量：95.41 GB / 套餐到期 / 官网 / 节点超时请手动更新订阅` 等信息节点，
  它们**测速真的能通**（119~152ms），按"测不通"是过滤不掉的。

### 结论
一条根因贯穿两个症状：**决策要先把所有候选逐个测一遍（85 个 = 50~70s）**，
而且 `guard !pingingAll` 让「全部测速」期间完全不能换节点。
用户在 UI 上看到"超时"后要等一分钟才动，于是认为"不切换"。附带问题：设备守护脚本 `BATCH=4`，
同样是 60~70s；两台引擎（App + 设备）各跑一套，互相抢路由器。

### 改动
- `ClashBackend.testGroupDelay(group:timeoutMs:)` + `ClashDelayProbe`（新增共享实现）；
  OpenClash/MaoMao 各自实现；`testDelay` 加 `timeoutMs` 参数（超时 5s → 3s）。
- `AppState`：新增 `probeDelays`（优先整组测速，多组并发，覆盖不到才逐个兜底）、
  `coveringGroups`、`groupDelayOnce`、`applyDelays`；`pingGroup` 重写为"一次请求 + 单次 UI 更新"；
  `failoverAfterTimeout` → `evaluateFailover(currentDelay:manual:preMeasured:)`；
  手动点击不受自动开关限制、所有提前 return 都给出 notice；加 40ms 切换回差；
  整组测速显示当前节点是通的就当成抖动不换。
- `MaoMaoService.refresh`：订阅列表只在 full 刷新读（原来每 3s 读一次 config.yaml，走 UFI root shell）；
  `startPolling` 设备状态 3s → 15s；测速期间不覆盖 `snapshot.groups`。
- `NodeFailoverScript`（设备守护）：`probe_group_once`/`pick_best_from_gres`/`json_map_pairs`（用 jq）
  走整组测速快路径，`BATCH=4→12`、`DELAY_TIMEOUT=5000→4000`，新增内置垃圾词表
  `ALWAYS_EXCLUDE_KEYWORDS`。`Models.phaseTitle` 补 `slow or timeout`/`no faster candidate` 文案。

### 验证
- macOS 侧同构请求（`/tmp/probe_check.swift`）：单节点 0.20s / 死节点 3.01s / **整组 3.01s 拿到 53 个可用**，
  按用户的关键词+地区过滤后剩 44 个候选（最快 🇯🇵 日本01 76ms）。

  **5 秒**返回 `🇯🇵 日本01 81ms`；垃圾节点 5/5 被排除、真实节点保留。
- 复刻 `UFIClient.writeFile` 的写入命令 3/3 一致（20KB 脚本，base64 27KB 一次成功）。
- `swift build -c release --disable-sandbox` 通过；已打包到 `dist/Clash Remote.app`（ad-hoc 签名）。
