实验一 · 进程同步

十字路口交通信号灯管理

用一个真实的城市路口，把临界资源、互斥、信号量、P/V 操作这些抽象概念，变成看得见的运行过程。

01

把"路口"翻译成"操作系统"

第一步是把日常问题抽象化。看起来平平无奇的红绿灯，其实就是一个教科书级别的并发问题。

现实问题 ↔ 操作系统概念

  • 十字路口  =  临界资源（critical resource）
  • 南北/东西车流  =  多个并发进程（processes）
  • 同时通行  =  数据竞争 → 撞车
  • 红绿灯  =  同步机制（synchronization）
  • 红绿切换  =  P/V 操作（信号量原语）
02

简化模型：适合初学者

真实路口很复杂（黄灯、左转、行人、感应触发…）。先把"主轴"理清楚，再一点点加东西。下面这些假设，是为了让模型可以被完整理解。

只有红绿，没有黄灯。切换是瞬时的，没有过渡相位。

4 个方向归并为 2 组：南+北 看作一组，东+西 看作一组。

固定时长：每组绿灯各持续 T 秒，循环切换。

每辆车 = 一个线程。车到了就尝试通过路口。

03

核心：信号量怎么设计

信号量是 Dijkstra 提出来的同步原语。对应的就是 acquire/release 两个动作，也叫 P/V。

思路

临界资源
路口（一次只能一个方向占用）
互斥要求
南北绿 ↔ 东西红，二者必须互斥
同步方法
两个信号量，分配"通行许可证"
许可证总数
恒等于 1（在两组之间转移）

PV 操作

P(s)
申请一个资源，s 值 -1。若 s<0 则阻塞
V(s)
释放一个资源，s 值 +1。若有等待者则唤醒
对应 Python
s.acquire() / s.release()
本质
操作系统保证 P/V 是原子操作（不可被打断）

状态转移：信号灯切换的瞬间

阶段 1
南北绿、东西红
ns_go = 1, ew_go = 0
P(ns) + V(ew)
阶段 2
东西绿、南北红
ns_go = 0, ew_go = 1
P(ew) + V(ns)
回到阶段 1
南北绿、东西红
ns_go = 1, ew_go = 0

关键点：许可证总数恒为 1，只是在切换时从一组"转移"到另一组。这就是教科书里讲的"信号量作为同步工具"的用法。

04

Python 完整实现

用 threading.Semaphore 模拟 PV 操作。复制即可运行。

traffic_light.py Python 3 
"""
十字路口交通信号灯管理（最简化模型）
- 只考虑红绿两色，瞬时切换
- 4 方向归并为 2 组（南北 / 东西）
- 用两个信号量分别控制两组通行权
"""
import threading
import time
import random

# ============ 信号量定义 ============
# 初始状态：南北通行、东西等待
ns_go = threading.Semaphore(1)   # 南北的"通行证"
ew_go = threading.Semaphore(0)   # 东西的"通行证"

NS_GREEN_TIME = 4   # 南北绿灯持续秒数
EW_GREEN_TIME = 4   # 东西绿灯持续秒数


# ============ 车辆线程 ============
def ns_car(car_id):
    """南北方向的车：每辆都是一个'进程'"""
    while True:
        ns_go.acquire()          # P(ns_go)：申请南北通行证
        print(f"  [南北] 车 {car_id:02d} 通过路口 @ {time.strftime('%H:%M:%S')}")
        time.sleep(0.3)             # 模拟通过路口用时
        # 注意：通过后不 release —— 由信号灯在切换时统一收回


def ew_car(car_id):
    while True:
        ew_go.acquire()          # P(ew_go)：申请东西通行证
        print(f"  [东西] 车 {car_id:02d} 通过路口 @ {time.strftime('%H:%M:%S')}")
        time.sleep(0.3)


# ============ 信号灯主控线程 ============
def light_controller():
    """周期性切换红绿红绿……"""
    cycle = 0
    while True:
        cycle += 1

        if cycle % 2 == 1:
            # ---------- 阶段 A：南北绿、东西红 ----------
            print(f"\n[信号灯] 南北【绿】 东西【红】 持续 {NS_GREEN_TIME}s")
            time.sleep(NS_GREEN_TIME)

            # 切换：把通行证从 NS 收回，发放给 EW
            # 用非阻塞 acquire 收回（若已被消费则返回，不影响）
            if ns_go.acquire(blocking=False): pass
            ew_go.release()           # V(ew_go)

        else:
            # ---------- 阶段 B：东西绿、南北红 ----------
            print(f"\n[信号灯] 东西【绿】 南北【红】 持续 {EW_GREEN_TIME}s")
            time.sleep(EW_GREEN_TIME)

            # 切换：把通行证从 EW 收回，发放给 NS
            if ew_go.acquire(blocking=False): pass
            ns_go.release()           # V(ns_go)


# ============ 启动 ============
if __name__ == "__main__":
    threads = []

    # 1 个信号灯主控
    t = threading.Thread(target=light_controller, daemon=True)
    t.start()

    # 3 辆南北车 + 3 辆东西车
    for i in range(3):
        threading.Thread(target=ns_car, args=(i+1,), daemon=True).start()
        threading.Thread(target=ew_car, args=(i+1,), daemon=True).start()

    time.sleep(20)     # 跑 20 秒看效果
    print("\n[主] 实验结束。")
▶ 运行命令：python3 traffic_light.py

07

核心要点

回头看一遍这次实验到底在讲什么。

1

临界资源 = 路口

任何时刻只能有一个方向占用。如果不限制，两组车会"撞"在一起——这就是数据竞争。

2

互斥靠信号量实现

两组信号量 ns_go / ew_go 总令牌数恒为 1。一组持有令牌时，另一组必须阻塞。

3

P/V 是原子操作

这是 OS 提供的保证——acquire 和 release 中途不会切换到别的线程。否则可能两个线程都"以为"自己拿到了令牌。

4

同步靠信号灯主控线程

信号灯以固定节奏切换，是整个系统的"节拍器"。这跟现实红绿灯由单片机定时器触发是一回事。

5

车是"被动"的

车辆线程不参与决策，只负责"申请→通过→再来"。控制权在信号灯主控。这是经典的控制者-工作者模式。

08

动手前可以想想

进阶问题 1：黄灯怎么加？

现实里切换前会有 3 秒黄灯全速变为"即将清场"。提示：再加一组信号量作为"黄灯阶段"，或者用一个 state 变量记录 3 种状态。

进阶问题 2：左转相位

真实路口左转需要单独的相位（直行绿+左转红、左转绿+直行红）。这意味着不再只有"南北 vs 东西"两组，而是 4 个相位。你能改成 4 阶段循环吗？

进阶问题 3：自适应时长

真实系统会根据车流密度动态调整绿灯时长。你可以加一个"车流计数器"，哪边车多就给哪边更长的绿。

进阶问题 4：行人按钮

加入"行人请求"：行人按下按钮后，下一个切换周期里强制加一段"行人过街"相位。提示：用 Condition 或 Event 让信号灯可以被打断。
